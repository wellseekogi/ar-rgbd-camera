# 화면 방향과 검수

- 사용자: 카메라를 설치하는 팀원과 게임 진행자. 노트북에서는 영상·깊이·연결 상태를, 폰에서는 촬영 상태를 확인합니다.
- 방향: 차분함·명확함·실시간 확인. 어두운 중립 바탕과 연두색 주 행동을 사용하고, 경고·용암은 상태색과 텍스트로 구분합니다.
- 화면 골격: 영상이 가장 큰 영역이며, 시간·생명·바닥 위치는 옆에 둡니다. 카메라별 보정 작업은 아래에 모았습니다.
- 상태: 연결 전·접속 키 오류·연결 중·촬영 중·보정 필요·모델 준비·깊이 대기·추적 끊김·게임 중지·성공·실패를 표시합니다.
- 현재 기본 전송은 HTTPS/WSS입니다. QR로 키·카메라 번호를 입력하며, 서버 접속과 실제 영상 수신을 구분해 표시합니다. 수신 중일 때만 상태를 강조하고, 연결이 끊기면 FPS를 0으로 표시하고 이전 영상을 지웁니다. QR에는 접속 키가 포함된다는 안내를 표시합니다.
- 검수 크기: 1440px와 390px. 브라우저 자동 검사 결과와 스크린샷은 `data/`에 생성합니다. 실제 사용자 테스트를 수행했다고 주장하지 않습니다.
- 예외: 카메라별 독립 작업은 한 화면에 여러 버튼이 필요합니다. 입력·포커스·카메라 상태 구분에는 경계선을 사용합니다.

## 자동 보정·거리별 색상 화면

- 핵심 행동: 폰을 움직여 기준판 조건을 채우고 다음 지시를 따릅니다. 차분함·직접적인 안내·확인 가능한 상태를 유지하며, Face ID의 진행 링과 체크 피드백을 참고했습니다. 기존 어두운 배경과 연두 상태색을 이어받고 장식 모션은 추가하지 않았습니다.
- 반복 요소는 분절된 진행 링, `✓/○` 체크와 다음 동작 한 문장입니다. 촬영 위치·거리·기울기는 실제로 채택한 사진만 체크합니다. 폰에는 실시간 인식 테두리를 겹치며, 노트북은 선택한 카메라의 다음 동작을 영상 위에 표시합니다.
- 저장된 렌즈 보정은 재사용 사실을 표시하며 사진 0장을 12장 촬영한 것처럼 표시하지 않습니다. 연결 끊김·기준판 미인식·흐림·이동·보정 실패·수동 모드·부분 보정·완료를 구별합니다. 기존 수동 조작은 접힌 상세 영역에 유지했습니다.
- 색상 깊이맵은 빨강→노랑→초록→파랑의 미터 범례, 중앙 깊이 수치, 측정 불가(검정) 설명을 함께 표시합니다. 원본과 색상을 같은 좌표로 맞추고 겹쳐 볼 수 있습니다. 과거 깊이는 연결·수신 만료 시 지웁니다.
- 1440px·390px 렌더링과 가로 넘침, 실제 색상 픽셀, 체크 상태 전환·버튼·표시 모드 전환을 브라우저 검사로 확인했습니다. 스크린샷은 `data/depth-guide-1440.png`, `data/depth-guide-390.png`, `data/guide-phone-cam1.png`입니다. 화면 검사용 합성 깊이를 실측 결과로 설명하지 않습니다. 실물 폰 사용자 테스트·물리 정확도 검증은 남아 있습니다.

## 두 카메라·깊이·REST 로그를 같은 화면에서 확인

사용자의 핵심 작업은 기존 웹에서 두 카메라 영상, 깊이 색상과 실제 반환 내용을 함께 확인하는 것입니다. 별도 검수 페이지를 만들지 않고 기존 스튜디오의 QR 다음에 세 열 모니터와 REST 로그를 배치했습니다. 방향은 직접 확인·명확한 오류·같은 화면이며 기존 네이비 바탕과 연두 상태색을 유지했습니다. 반복되는 요소는 영상 번호 `01/02/Z`와 텍스트가 동반된 수신 상태입니다.

두 카메라 수신이 확인되면 QR 영역이 한 번 자동으로 접혀 모니터가 중심이 됩니다. QR은 다시 펼칠 수 있습니다. 기존 게임 합성, 전체 화면, 보정·규칙 설정, 보조 카메라 기능은 유지했습니다. 모바일은 영상과 깊이를 세로로 배치합니다. 깊이와 같은 시점의 원본 확인 방법을 명시해 최신 카메라 화면과 깊이가 항상 같은 프레임이라고 오해하지 않게 했습니다.

REST 로그는 실제 `GET /api/rgbd/frame`의 HTTP 상태·소요시간·응답 크기와 JSON 구조를 표시합니다. Base64 본문은 앞 48자와 전체 문자 수만 표시하며 실제 API 반환은 바꾸지 않습니다. 200·409·통신 오류, 일시정지·다시 시작·비우기를 구별하고 최대 20개 기록을 유지합니다. 접속 키는 로그에 넣지 않습니다. 응답 뒤 1초 후 다음 요청을 보내므로 요청이 중첩되지 않습니다.

1440px·390px에서 전후 레이아웃과 가로 넘침을 확인했습니다. `data/live-monitor-1440.png`, `data/live-monitor-390.png`는 REST UI 검사용 응답을 사용한 화면입니다. 실제 GPU 깊이 성공 증거로 사용하지 않습니다. 가상 카메라 연결은 실제 WebSocket 수신 경로를 별도로 검사했습니다. 실제 사람·기기의 지연과 조작성은 미검증입니다.
